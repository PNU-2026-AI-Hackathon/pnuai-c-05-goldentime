# 코드 발췌 (excerpts)

전체 애플리케이션은 비공개 저장소에 있습니다. 이 폴더는 **팀이 어떤 규율로 코드를 쓰는지**
보여주기 위한 발췌이며, 그 자체로 실행되는 앱이 아닙니다. 빌드에서 제외됩니다
(`tsconfig.json`의 `exclude`).

**공개한 것과 제외한 것의 기준:** 제품의 해자는 프롬프트가 아니라 임상 자문·검증 축적·
데이터 규율이라고 판단했습니다. 그래서 아래처럼 갈랐습니다.

| | 내용 |
|---|---|
| **공개** | 비식별, 인용 검증, 수치 추출 — 모두 순수 함수 + 테스트 |
| **제외** | 분과별 프롬프트 렌즈, 3-모델 검증 하네스 내부, 사업 전략 문서 |

---

## `deid/` — 비식별 (99줄 + 규칙 68줄 + 테스트 132줄)

환자 식별자를 마스킹합니다. 핵심 설계 두 가지:

1. **날짜는 지우지 않고 시프트**합니다. 지워버리면 "2주 후 재발" 같은 **간격 정보**가 사라져
   시계열 요약 자체가 불가능해지기 때문입니다.
2. **저장 직전 재검사**로, 마스킹 후에도 식별자가 남아 있으면 **저장을 거부**합니다.
   (실제로 이 가드가 시프트된 날짜를 오인해 정상 저장을 막은 사고가 있었고,
   `docs/TROUBLESHOOTING.md`에 기록돼 있습니다.)

## `citation/` — 인용 검증 (환각 차단의 핵심)

`enforce.ts`는 25줄짜리 순수 함수지만 제품 주장 전체가 여기 걸려 있습니다.

- 모델이 붙인 인용 ID가 **실제 청크와 매칭되지 않으면 그 문장을 버립니다**
- `span.ts`는 인용 구절이 **그 청크 본문에 실재하는지** 확인합니다. 창작된 인용은 통과 못 합니다
- 즉 화면에 남는 문장은 전부 원문의 특정 위치를 가리키며, 클릭하면 그 자리로 이동합니다

## `vitals/` — 검사 수치 추출 (48줄 테스트 포함)

요약 문장에서 검사 수치를 뽑아 타일로 보여줍니다. **화이트리스트 방식**을 쓴 이유가 중요합니다 —
일반 정규식으로 "이름 + 숫자"를 잡으면 `DES 1개`(스텐트 개수)나 인용 표기 `[c44]`가 검사
수치로 둔갑합니다. 의료 화면에서 그건 오탈자보다 위험한 사고라, **모르는 이름은 아예 안 뽑습니다.**
테스트에 그 오인 방어 케이스가 들어 있습니다.

## 읽는 법

파일은 실제 코드 **그대로**입니다. 다만 발췌만으로도 읽히도록 두 가지를 보완했습니다.

- `chunking.ts`를 이 폴더 최상단에 두어 `citation/enforce.ts`의 상대 경로가 맞도록 했습니다
- `vitals/summarize.ts`는 `vitals.ts`가 참조하는 **타입 정의만** 발췌한 것입니다
  (전체 `summarize.ts`는 비공개)

테스트는 [Vitest](https://vitest.dev) 기준으로 작성돼 있으며, 이 저장소에는 러너가
설치돼 있지 않습니다(랜딩 앱과 의존성을 섞지 않기 위함). 비공개 저장소에서는 전체
**152개 테스트**가 통과합니다.
