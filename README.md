# 차트원샷 · ChartOneShot

> **길고 복잡한 차트에서, 내 분과에서 필요한 것만.**

여러 차수에 걸쳐 누적된 한국어 EMR을 **환자 단위 시계열 요약**으로 정리하는 의료 AI입니다.
저희가 우선한 것은 속도가 아니라 **근거를 확인할 수 있는 요약**입니다. 표시하는 문장에는
원문 근거를 붙이고, 근거를 확인하지 못한 문장은 화면에 내보내지 않습니다.

🔗 **Live: https://chartoneshot-demo.vercel.app**

## 1. 프로젝트 소개

### 1.1. 개발 배경 및 필요성

- 한 환자의 EMR에는 여러 차수의 외래·입원 기록이 누적되어, 한국어 약어가 뒤섞인 길고
  반복적인 텍스트가 쌓입니다.
- 의사가 복잡한 케이스 하나를 검토하는 데 평균 **약 25분**이 소요된다는 보고가 있습니다.
  *(Nolan et al., Applied Clinical Informatics, 2017)*
- 임상실습 의대생·전공의는 차트를 빠르게 읽는 경험이 부족해, 확인해야 할 흐름을 놓치기
  쉽습니다.
- 환자 정보는 외부 반출이 제한되어, 일반적인 클라우드 서비스를 그대로 적용하기 어려운
  제약이 있습니다.

### 1.2. 개발 목표

- 길고 반복적인 EMR에서 **의사가 확인해야 할 흐름**을 중심으로 정리
- 요약 문장에 **원문 인용을 함께 제시**하고, 근거가 확인되지 않은 문장은 표시하지 않음
- 불확실한 부분과 누락을 **감추지 않고 드러내는** 요약
- 장기적으로 기관 내부 환경에서 운용 가능한 구조로 이행

### 1.3. 접근 방식의 특징

| 구분 | 일반적인 요약 | **차트원샷의 접근** |
|---|---|---|
| 근거 제시 | 요약문만 제공 | 문장마다 **원문 인용을 함께 표시** |
| 근거 추적 | 어려움 | 문장을 누르면 **원문의 해당 위치로 이동** |
| 불확실성 | 드러나지 않음 | **원문 / 추론 / 불확실** 구분 표시 |
| 누락 | 알기 어려움 | 요약이 **다루지 못한 부분**을 별도로 표시 |
| 검증 | 자체 판단 | 합성 케이스를 **여러 모델에 각각 실행해 결과를 대조** |

### 1.4. 사회적 가치

- **의료 형평성**: 차트 판독 경험이 적은 의대생·전공의의 학습과 확인을 지원
- **환자 안전**: 근거 제시와 불확실성 표시로 오판 가능성을 줄이는 방향
- **개인정보 보호**: 비식별 처리 후 사용하며, 식별자가 남아 있으면 저장하지 않음
- **정직한 기록**: 잘 된 것뿐 아니라 **문제가 있었던 부분도 기록으로 공개**(3.4)

> 본 프로젝트는 연구·개발 단계이며, 임상적 유효성은 아직 검증되지 않았습니다.
> 진료 판단을 대체하지 않으며, 의료기기로 개발된 것이 아닙니다.

## 2. 상세 설계

### 2.1. 현재 구현 범위와 향후 방향

> 아래 "향후 방향"은 **아직 구현되지 않은 계획**입니다.

| 영역 | **현재** | **향후 방향** |
|---|---|---|
| 요약 | 상용 LLM API + 인용 제시 | 기관 내부에서 운용 가능한 형태 |
| 검증 | 합성 케이스를 여러 모델에 실행해 결과 대조 | 자문 교수진 검토 결과를 축적 |
| 데이터 | 합성 차트 | 기관 승인 절차를 거친 데이터 |
| 배포 | 웹 서비스 | 기관 환경 적용 검토 |

### 2.2. 처리 흐름

```
EMR 텍스트 입력
   │
   ▼
[비식별]   이름·식별번호·연락처 등 마스킹
   │       날짜는 삭제하지 않고 이동(간격 정보 보존)
   ▼
[분할]     구간마다 인용 번호 부여
   │
   ▼
[요약]     분과 관점에서 정리 — 문장마다 인용 번호와 인용 구절을 함께 생성
   │
   ▼
[인용 확인] ① 인용 번호가 실제 구간과 맞는가
   │        ② 인용 구절이 그 구간에 실제로 있는가
   │        → 확인되지 않으면 그 문장을 표시하지 않음
   ▼
[출력]     원문과 요약을 나란히 보여주고, 문장을 누르면 원문 위치로 이동
```

검증 단계에서는 같은 케이스를 **서로 다른 모델에 각각 실행**해 결과가 갈리는 구간을 찾고,
그 기록을 남깁니다.

### 2.3. 사용 기술

**Frontend / App**
- Next.js (App Router) · React · TypeScript · Tailwind CSS
- Framer Motion · lucide-react

**Backend**
- Next.js Route Handlers · 서버리스 함수
- PostgreSQL 기반 관리형 DB — 실행 기록 저장
- 파일 업로드 처리

**AI**
- 요약: 상용 LLM API (구조화 출력 + 인용 제시)
- 검증: 서로 다른 계열의 모델을 각각 실행해 결과 대조
- 의료 특화 오픈 모델을 검증용 참고 트랙으로 함께 실행

**품질 관리**
- TypeScript strict 모드 · 자동화 테스트 **152개**
- 배포 전 타입 검사·빌드·테스트 통과를 필수 절차로 운영

## 3. 개발 결과

### 3.1. 주요 기능

**① 차트 입력 → 비식별 → 요약 → 근거 대조**
합성 차트 샘플을 제공하며, 붙여넣기와 파일 업로드를 지원합니다. 비식별 결과를 **사용자가
직접 확인하고 수정한 뒤** 요약합니다.

**② 원문 대조 화면**
요약 문장을 누르면 원문의 해당 위치가 표시됩니다. 근거를 붙이지 못한 문장은 표시되지
않습니다.

**③ 근거 구분 표시**
문장마다 `원문 / 추론 / 불확실`을 구분합니다. 인용 구절까지 확인된 문장과 인용 구간까지만
확인된 문장도 구분해 표시합니다.

**④ 검사 수치 흐름**
검사값이 시간에 따라 어떻게 변했는지를 함께 보여줍니다. 현재 값만으로는 알기 어려운
변화를 확인하기 위한 것입니다.

**⑤ 모델 간 결과 대조**
같은 차트를 여러 모델에 각각 실행해, 결과가 일치하는 구간과 갈리는 구간을 보여줍니다.
각 모델의 출력 문장을 **그대로** 두고 원문 위치 기준으로만 정렬합니다.

**⑥ 실행 기록 공개**
합성 케이스에 대한 실행 기록을 공개합니다. 결과가 좋지 않았던 실행도 함께 싣습니다.

### 3.2. 공개 데이터

`data/synthetic-cases/` — 외과 · 응급의학과 · 안과 · 가정의학과 4종.

실제 의무기록의 **서식과 임상 논리 구조만 참고해 재작성한 합성 차트**이며, 인물·수치·날짜·
식별자는 모두 창작입니다. **실제 환자 정보는 포함돼 있지 않습니다.**

### 3.3. 코드 발췌

`excerpts/` — 비식별, 인용 확인, 수치 추출과 각 테스트.
자세한 설명은 [`excerpts/README.md`](excerpts/README.md).

### 3.4. 문제 기록 — `docs/DEVELOPMENT-NOTES.md`

검증을 앞세우는 팀이라면 **문제도 기록해야 한다**고 판단해, 날짜·증상·원인·수정·교훈을
남기고 있습니다. 예를 들어 개발 중 **저희 후처리 코드의 결함 때문에** 특정 모델의 결과가
전부 버려지고 있었던 적이 있습니다. 원인을 찾는 과정에서 저희가 두 차례 잘못 짚었고,
그 과정까지 기록에 남긴 뒤 수정하고 결과를 다시 공개했습니다.

### 3.5. AI 도구 활용

- **개발 도구**: Claude Code를 주 개발 도구로 사용했고, 다른 계열의 코딩 모델로 **교차 리뷰**를
  걸어 스스로 놓친 문제를 점검했습니다. 실제로 이 교차 리뷰가 배포 전에 여러 결함을
  잡아냈습니다.
- **제품**: 요약은 상용 LLM API를 사용하고, 검증 단계에서 여러 모델을 함께 실행합니다.
