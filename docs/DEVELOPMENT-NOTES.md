# 개발 기록 — 문제와 수정 (발췌)

저희는 개발 중 만난 문제를 만난 즉시 **날짜 · 증상 · 원인 · 수정 · 검증 · 교훈** 형식으로
기록합니다. 검증을 앞세우는 제품이라면 잘 된 것만 남겨서는 안 된다고 판단했기 때문입니다.

> 아래는 **공개 가능한 항목만 발췌**한 것입니다. 운영·보안 관련 내부 항목은 제외했습니다.
> 전체 기록은 비공개 저장소에서 관리하고 있습니다.

---

## 1. 날짜를 "남은 식별자"로 잘못 판단해 저장을 막던 문제

- **증상:** 비식별을 정상적으로 마친 차트인데도 저장이 거부되는 경우가 있었습니다.
- **원인:** 저희는 날짜를 **삭제하지 않고 일정하게 이동**시킵니다. "2주 후 재발" 같은
  **간격 정보**가 사라지면 시계열 요약 자체가 불가능해지기 때문입니다. 그런데 저장 직전
  최종 점검 로직이 이 **이동된 날짜를 아직 남아 있는 식별자로 오인**했습니다.
- **수정:** 최종 점검에서 날짜 항목을 판정 대상에서 분리했습니다. 이름·번호류에 대한
  차단은 그대로 유지했습니다.
- **교훈:** 안전장치는 **막아야 할 것과 남겨야 할 것을 구분**하지 못하면 오히려 기능을
  망가뜨립니다. 보수적으로 만드는 것과 무차별적으로 막는 것은 다릅니다.

## 2. 배포 환경변수가 비어 있는데 "설정됐다"고 보이던 문제

- **증상:** 배포 환경에서만 기능이 동작하지 않는데, 설정을 조회하면 정상으로 보였습니다.
- **원인:** 값 등록 과정에서 의도치 않은 문자가 섞였고, 조회 결과만으로는 이를 확인할 수
  없었습니다.
- **수정:** 값을 재등록하고, **설정 확인은 조회 결과가 아니라 실제 호출로 검증**하도록
  절차를 바꿨습니다.
- **교훈:** "설정돼 있다고 보이는 것"과 "실제로 동작하는 것"은 다릅니다. 확인은 **실행으로**
  합니다.

## 3. 문서 미리보기가 특정 환경에서만 실패하던 문제

- **증상:** PDF 미리보기가 일부 환경에서 생성되지 않았습니다.
- **원인:** 렌더링에 필요한 외부 도구가 해당 환경에 설치돼 있지 않았습니다.
- **수정:** 의존 도구를 명시하고, 없을 때는 기능을 조용히 실패시키지 않고 **원인을 표시**하도록
  했습니다.
- **교훈:** 조용한 실패는 없는 기능보다 나쁩니다.

## 4. 모델이 실패한 줄 알았는데, 저희 코드의 결함이었던 문제

- **증상:** 공개해 둔 실행 기록에서 특정 모델이 **실행 실패**로 표시돼 있었습니다.
- **최초 판단(오진 2회):** 처음에는 인프라 문제로, 다음에는 그 모델이 출처 표기를 못 하는
  문제로 각각 판단했습니다. **둘 다 틀렸습니다.**
- **원인:** 그 모델은 출처를 **문장 안에 함께 적는 방식**으로 표기하는데, 저희 후처리
  코드가 그 표기를 인식하지 못하고 버렸습니다. 그 결과 "근거 없는 문장"으로 분류돼
  **전부 삭제**되고 있었습니다. 모델은 정상적으로 답을 내고 있었습니다.
- **수정:** 해당 표기를 인식하도록 고치고, 회귀 테스트를 추가한 뒤 **다시 실행해 공개 기록을
  갱신**했습니다. 그리고 **정정 내용을 공개 페이지에 게시**했습니다.
- **교훈:**
  1. **관대한 파서는 실패를 삼킵니다.** 빠진 값을 조용히 기본값으로 채우면, 나중에
     "상대가 안 준 것"과 "우리가 채운 것"을 구분할 수 없게 됩니다.
  2. **후처리를 거친 데이터를 상대의 행동에 대한 증거로 쓰면 안 됩니다.** 진단은 항상
     가공되기 전 단계에서 시작해야 합니다.
  3. **남의 실패로 적혀 있던 것이 우리 문제일 수 있습니다.** 바로잡고 나니 설명이
     오히려 분명해졌습니다.

---

## 개발 과정에서 지킨 것

- 변경마다 **타입 검사 · 빌드 · 자동화 테스트(152개)** 통과를 확인한 뒤 배포했습니다.
- 주요 변경은 **다른 계열의 코딩 모델로 교차 리뷰**를 걸었습니다. 실제로 이 절차가
  자체 점검에서 놓친 문제들을 배포 전에 잡아냈습니다.
- 수치나 표현을 화면에 쓸 때는 **실제로 측정한 것만** 쓰는 것을 원칙으로 했습니다.
