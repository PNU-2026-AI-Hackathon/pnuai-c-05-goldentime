# 비식별 파이프라인에서 배운 것

> 개발 중 비식별 로직에서 결함 2건을 발견해 수정했습니다.
> 잘 된 것만 적으면 다음 사람이 같은 자리에서 넘어지므로, **무엇을 왜 놓쳤는지**를 남깁니다.
> 이 문서에는 어떤 실제 데이터도 포함되지 않으며, 예시 값은 전부 더미입니다.

## 결함 ① 자기 규칙으로 자기를 검사하면, 그건 가드가 아니라 거울입니다

**증상.** 마스킹 후 잔여 식별자를 확인하는 가드가 **"0건 — 깨끗함"** 을 보고했습니다.
그런데 다른 방법으로 다시 훑어보니 식별자가 그대로 남아 있었습니다.

**원인.** 가드가 `detect(masked)` 를 호출하고 있었습니다. 즉 **마스킹에 쓴 것과 똑같은 규칙**으로
검사한 것입니다. 탐지기가 못 본 값은 검사기도 똑같이 못 봅니다. 결국 이 가드가 확인한 것은
*"탐지기가 잡은 것을 탐지기가 다시 잡는가"* 였고, **탐지기의 맹점은 원리적으로 검출할 수 없는
구조**였습니다.

```
mask(detect(text))  →  residual_guard: detect(masked) == 0  →  "깨끗함"
                                        └─ 같은 규칙. 맹점도 그대로 상속된다
```

**이것이 저희 제품 철학과 정확히 같은 문제입니다.** 하나의 모델이 만든 요약을 같은 모델에게
검토시키면 대체로 통과시킵니다. 저희가 **서로 다른 백본으로 교차 검증**하는 이유가 이것입니다.
비식별에서 같은 실수를 하고 나서야 그 원칙이 코드 레벨에서도 지켜져야 한다는 걸 알았습니다.

**수정.** 잔여 검사를 **탐지에 쓰지 않은 독립 패턴셋**으로 분리했습니다. 다만 근본 구조는
남아 있습니다 — 완전한 해법은 규칙 기반이 아닌 별도 레이어(NER 모델 등)를 두는 것이고,
이는 **미해결 항목**으로 두고 있습니다.

## 결함 ② 한국어 라벨의 중의성 — `주소` 는 주소가 아닐 때가 많습니다

한국어 의무기록에서 `주소` 는 **主訴(chief complaint, 환자의 주된 호소)** 로 쓰이는 경우가
많습니다. 라벨만 보고 줄 끝까지 마스킹하면 이렇게 됩니다.

```
주 소 : 복통 3일째, 오심 동반   →   주 소 : ███      ← 임상 정보가 사라짐
```

**이것은 PHI 유출의 정반대 실패입니다.** 그리고 더 조용합니다 — 에러가 나지 않고 요약 품질
저하로만 나타나서 원인을 되짚기 어렵습니다.

**수정.** 라벨의 중의성 유무로 갈랐습니다.

| 라벨 | 처리 |
|---|---|
| `주소지` · `현주소` · `거주지` (뜻이 하나) | 값 검증 없이 마스킹 |
| `주 소` (중의적) | **값이 행정구역 패턴을 포함할 때만** 주소로 인정 |

행정구역 판정은 `[가-힣]{2,}(시\|도\|군\|구\|읍\|면\|동\|리\|로\|길\|가)\s*\d` 를 lookahead 로 확인합니다.
주소는 여전히 가려지고 主訴 문장은 원문 그대로 남는 것을 양방향으로 검증했습니다.

## 정규식이 비껴간 세 가지 유형

| 유형 | 왜 안 걸리나 |
|---|---|
| **라벨과 값의 분리 배치** | 표 형태 문서는 텍스트 추출 시 렌더 순서를 따라 **라벨 3개가 먼저, 값 3개가 나중에** 나옵니다. `(?:성명\|환자명)[:\s]*(값)` 처럼 라벨 바로 뒤에 값이 있다고 가정한 패턴은 잡지 못하거나 엉뚱한 것을 잡습니다 |
| **이미 일부가 마스킹된 번호** | 뒷자리가 `*******` 로 가려져 배포되는 서식이 있습니다. `\d{6}-\d{7}` 에 안 걸립니다. 그런데 **앞 6자리는 생년월일 그 자체**라 그대로 두면 재식별 재료입니다 |
| **하이픈으로 구획된 번호** | `000-00-00-0` 같은 형식은 연속 숫자 패턴 `\d{4,}` 를 비껴갑니다 |

```
등록번호:
성    명:
주민번호:
000-00-00-0
F
홍길동
000000-*******
```

*(위 블록의 값은 전부 명백한 더미입니다. 재현해야 하는 것은 값이 아니라 **배치 구조** 입니다.)*

## 테스트 픽스처 규칙 — 대체값은 한눈에 가짜여야 합니다

회귀 테스트를 만들 때 처음에는 *그럴듯한* 가명을 썼습니다. 실제 인명 형태, 실제 번호 형식으로요.
**이것이 잘못된 선택이었습니다.** 리뷰어나 시크릿 스캐너 입장에서는 그것이 진짜인지 가짜인지
구분할 방법이 없습니다. 다음 사람이 보면 사고로 오인하고, 결국 불필요한 정리 작업을 부릅니다.

그래서 규칙을 세웠습니다.

> **구조만 베끼고 값은 처음부터 창작한다. 대체값은 한눈에 가짜로 읽혀야 한다.**
> (`홍길동` · `000-00-00-0` · `000000-*******` · `테헤란로 123`)

정규식이 검증하는 것은 자릿수·하이픈 구획·마스킹된 뒷자리 같은 **구조**이므로,
값을 명백한 더미로 바꿔도 검증력은 그대로입니다.

## 교훈 요약

1. **자기 규칙으로 자기를 검사하면 맹점이 그대로 상속된다.** 검사자는 탐지자와 규칙이 달라야 한다.
2. **비식별의 실패는 두 방향이고 둘 다 위험하다.** 놓치면 유출, 과잉이면 임상 정보 손실.
   후자는 에러가 안 나서 더 늦게 발견된다.
3. **우리가 만든 형식으로 만든 샘플은 우리 규칙을 항상 통과한다.** 서식이 다른 문서를
   넣어보기 전까지 비식별은 미검증 상태로 봐야 한다.
4. **한국어 의무기록은 라벨 중의성이 있다.** `주소`/`主訴` 외에도 유사 사례 전수 점검은 아직 못 했다.
5. **픽스처의 대체값은 한눈에 가짜여야 한다.**

## 남은 한계 (정직하게)

- 잔여 검사를 독립 패턴으로 분리했지만 **여전히 규칙 기반**입니다. 규칙이 모르는 형식은 여전히 못 잡습니다.
- 검증에 쓴 **서식 표본이 적습니다.** 기관마다 서식이 달라 일반화할 수 없습니다.
- 라벨 중의성은 `주소`/`主訴` 만 처리했습니다. `경과`/`經過`, `처방`/`處方` 등 **전수 점검은 미실시**입니다.
