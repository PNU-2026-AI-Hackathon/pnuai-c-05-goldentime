## 0. 먼저 — 우리가 만들려는 게 뭔가

환자 한 명의 진료 기록이 5년치 쌓여 있습니다. 외래 30번, 입원 2번, 검사지 수십 장. 교수님이 이걸 다 읽으려면 25분이 걸립니다.

우리가 만드는 건 **"이 환자, 지금 뭐가 중요한가"를 한 장으로 뽑아주는 프로그램**입니다.

중요한 건 이겁니다 — **AI가 지어내면 안 됩니다.** 그래서 우리는 모든 문장에 "이 말은 원본 몇 페이지 몇 번째 줄에서 나왔다"는 꼬리표를 강제로 붙입니다. 꼬리표를 못 다는 문장은 **버립니다.** 이게 이 프로젝트의 전부라고 해도 됩니다.

### 비유 하나

**AI를 "기억력 나쁜 똑똑한 인턴"이라고 생각하세요.**

- 똑똑합니다 → 요약을 잘합니다
- 기억력이 나쁩니다 → 긴 차트를 한 번에 못 읽습니다 → 그래서 **RAG**(필요한 페이지만 찾아서 줌)
- 가끔 지어냅니다 → 그래서 **원문 인용 강제**(출처 못 대면 그 말은 삭제)
- 우리 병원 용어를 모릅니다 → 그래서 **약어 사전**과 **LoRA**(우리 방식으로 살짝 가르치기)

이 네 가지가 이 문서의 실습 A~D입니다.

## 1. 용어 10개 — 이것만 알면 됩니다

| 용어 | 쉽게 말하면 | 왜 중요한가 |
|---|---|---|
| **GPU** | AI 계산 전용 부품. 그래픽카드 | 없으면 AI가 안 돌아갑니다 |
| **VRAM** | GPU의 작업 책상 크기 (GB) | **모델이 책상보다 크면 아예 안 켜집니다** |
| **모델** | AI의 두뇌 파일. 수십 GB짜리 파일 하나 | 우리는 이걸 다운받아 씁니다 |
| **파라미터(B)** | 두뇌 크기. "27B" = 270억 개 | 클수록 똑똑하지만 책상을 많이 씁니다 |
| **양자화** | 파일을 압축해 책상을 덜 쓰게 | 27B가 54GB → **4-bit로 13.5GB** |
| **토큰** | AI가 읽는 글자 단위. 한글 1자 ≈ 1~2토큰 | 요금·속도·한계가 다 토큰 기준 |
| **컨텍스트** | 한 번에 읽을 수 있는 최대 토큰 | 이걸 넘으면 앞부분을 잊습니다 |
| **임베딩** | 문장을 숫자 목록으로 바꾸기 | 뜻이 비슷하면 숫자도 비슷해집니다 |
| **벡터DB** | 그 숫자들을 넣어두고 "비슷한 거 찾아줘" 하는 창고 | RAG의 핵심 부품 |
| **LoRA** | 두뇌 전체를 바꾸지 않고 **작은 메모지만 덧붙여** 가르치기 | 우리가 할 수 있는 유일한 학습법 |

### 양자화를 조금 더

모델 파일은 숫자 덩어리입니다. 원래 숫자 하나에 **16비트**를 씁니다.

```
27B 모델을 16비트로 = 27,000,000,000 × 2바이트 = 약 54GB   → 4080(16GB)에 안 들어감
27B 모델을 4비트로  = 27,000,000,000 × 0.5바이트 = 약 13.5GB → 겨우 들어감
```

숫자의 정밀도를 낮추는 겁니다. 사진을 JPEG로 줄이는 것과 비슷합니다. 조금 흐려지지만 알아볼 수 있습니다.

**그래서 우리는 항상 4-bit(NF4)로 씁니다.** 안 그러면 못 켭니다.

## 3. 실습 A — 모델을 내 컴퓨터에서 돌려보기

목표: **"AI가 내 컴퓨터에서 돌아간다"를 눈으로 확인**

### A-1. 가장 쉬운 방법 (Ollama)

Ollama는 "AI 모델계의 앱스토어"입니다. 명령어 한 줄로 받고 바로 씁니다.

```bash
# 설치 (한 번만)
curl -fsSL https://ollama.com/install.sh | sh

# 모델 받기 — 20B 모델, 약 12GB 다운로드. 커피 한 잔 시간
ollama pull gpt-oss:20b

# 대화해보기
ollama run gpt-oss:20b
```

이러면 채팅창이 뜹니다. 여기에 이렇게 쳐보세요:

```
다음 진료기록을 3줄로 요약해줘.

2024-03-12 외래. 45세 여자. 체중 92kg, BMI 34.1.
당뇨약 메트포르민 복용 중. HbA1c 7.8%.
식이 상담 시행. 3개월 후 f/u 예정.
```

**요약이 나오면 성공입니다.** 이 순간 당신 컴퓨터 안에서 AI가 돈 겁니다. 인터넷으로 아무 데도 안 보냈습니다.

### A-2. 확인해볼 것

다른 터미널을 열고:

```bash
nvidia-smi
```

`Memory-Usage`가 `12000MiB / 16376MiB` 같이 나옵니다. **모델이 GPU 책상을 12GB 쓰고 있다는 뜻**입니다. 이게 16GB를 넘으면 에러가 납니다.

### A-3. 왜 Ollama로 끝내지 않는가

Ollama는 사람이 채팅하기 좋지만, **프로그램이 부르기엔** vLLM이 낫습니다. 빠르고, 동시 처리가 되고, 무엇보다:

> **vLLM은 "OpenAI와 똑같은 방식"으로 말을 겁니다.**

이게 왜 중요하냐면 — 우리가 이미 만든 차트원샷 코드가 OpenAI 방식으로 짜여 있습니다. **주소만 바꾸면 그대로 돌아갑니다.** 코드를 다시 안 짜도 됩니다.

```bash
pip install vllm

# 서버 띄우기
vllm serve openai/gpt-oss-20b \
  --quantization bitsandbytes \
  --max-model-len 8192 \
  --port 8000
```

띄운 뒤 다른 창에서:

```bash
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-oss-20b",
    "messages": [{"role":"user","content":"안녕? 한 줄로 답해줘"}],
    "temperature": 0
  }'
```

JSON으로 답이 오면 성공입니다.

**`temperature: 0`이 중요합니다.** 이건 "창의성 0" 설정입니다. 의료에서는 매번 다른 답이 나오면 안 되니까 항상 0에 가깝게 씁니다.

## 4. 실습 B — 요약 파이프라인 한 바퀴

목표: **차트 → 조각내기 → 숫자로 바꾸기 → 찾기 → 요약** 전 과정을 눈으로 보기

### B-1. 왜 차트를 조각내나 (청킹)

AI는 한 번에 8,000토큰 정도만 읽습니다. 5년치 차트는 10만 토큰이 넘습니다. **다 못 읽습니다.**

그래서 조각냅니다. 아무렇게나 자르는 게 아니라 **"외래 1회분", "입원 1차분"** 같은 자연스러운 단위로 자릅니다.

```python
# chunk_demo.py
chart = """
[2024-03-12 외래]
45세 여자. 체중 92kg, BMI 34.1. 메트포르민 복용 중. HbA1c 7.8%.
식이 상담 시행. 3개월 후 f/u 예정.

[2024-06-20 외래]
체중 87kg, BMI 32.3. HbA1c 7.1%로 개선. 운동 병행 중.

[2024-09-15 외래]
체중 85kg. 지방간 소견으로 복부초음파 시행 예정.
"""

# 대괄호로 시작하는 줄에서 자른다
chunks = [c.strip() for c in chart.split('\n\n') if c.strip()]

for i, c in enumerate(chunks):
    print(f"--- 청크 {i}  (인용ID: c{i}) ---")
    print(c)
    print()
```

돌려보면 3조각이 나옵니다. 각 조각에 **`c0`, `c1`, `c2`라는 이름표**를 붙였습니다.

**이 이름표가 나중에 "출처"가 됩니다.** AI가 "체중이 92kg에서 85kg으로 감소"라고 말하면, 우리는 "그 근거가 c0과 c2에 있네" 하고 확인할 수 있습니다.

### B-2. 문장을 숫자로 (임베딩)

```bash
pip install sentence-transformers
```

```python
# embed_demo.py
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("google/embeddinggemma-300m")

a = model.encode("체중이 줄었다")
b = model.encode("몸무게가 감소했다")
c = model.encode("오늘 날씨가 좋다")

print("숫자 개수:", len(a))          # 768개쯤

from numpy import dot
from numpy.linalg import norm
sim = lambda x, y: dot(x, y) / (norm(x) * norm(y))

print("체중↔몸무게 :", round(sim(a, b), 3))   # 0.9 근처 — 비슷하다
print("체중↔날씨   :", round(sim(a, c), 3))   # 0.2 근처 — 다르다
```

**이게 임베딩의 전부입니다.** 글자가 달라도 뜻이 비슷하면 숫자가 비슷해집니다.

키워드 검색은 "체중"으로 찾으면 "몸무게"를 못 찾습니다. 임베딩 검색은 찾습니다. **그래서 필요합니다.**

### B-3. 창고에 넣고 찾기 (벡터DB)

```bash
# Qdrant 띄우기 (도커)
docker run -p 6333:6333 qdrant/qdrant
```

```python
# rag_demo.py
from qdrant_client import QdrantClient
from qdrant_client.models import Distance, VectorParams, PointStruct
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("google/embeddinggemma-300m")
db = QdrantClient("localhost", port=6333)

db.recreate_collection(
    "charts",
    vectors_config=VectorParams(size=768, distance=Distance.COSINE),
)

chunks = [
    {"id": 0, "patient": "P001", "text": "2024-03-12 체중 92kg BMI 34.1 메트포르민"},
    {"id": 1, "patient": "P001", "text": "2024-06-20 체중 87kg HbA1c 7.1 개선"},
    {"id": 2, "patient": "P002", "text": "2024-05-01 체중 70kg 고혈압 약물 조정"},  # 다른 환자!
]

db.upsert("charts", points=[
    PointStruct(id=c["id"], vector=model.encode(c["text"]).tolist(), payload=c)
    for c in chunks
])

# ★ 반드시 환자 ID로 걸러서 검색한다
from qdrant_client.models import Filter, FieldCondition, MatchValue

hits = db.search(
    "charts",
    query_vector=model.encode("체중 변화").tolist(),
    query_filter=Filter(must=[FieldCondition(key="patient", match=MatchValue(value="P001"))]),
    limit=3,
)
for h in hits:
    print(round(h.score, 3), h.payload["text"])
```

> ### ★ 여기가 이 프로젝트에서 가장 위험한 한 줄입니다
>
> `query_filter`를 빼먹으면 **P001 환자 요약에 P002 환자 기록이 섞여 들어갑니다.**
> 비식별 데이터라도 이건 임상적으로 치명적이고, 논문 심사에서 제일 먼저 지적당합니다.
> **필터를 빼먹으면 테스트가 실패하도록** 회귀 테스트를 반드시 넣어야 합니다.

### B-4. 전부 이어붙이기

```
질문: "이 환자 체중 변화는?"
   ↓
임베딩으로 바꿈
   ↓
벡터DB에서 P001 것만 검색 → c0, c1이 나옴
   ↓
LLM에게 이렇게 물음:
   "아래 근거만 보고 답해. 근거에 없는 건 말하지 마.
    각 문장 끝에 [c번호]를 붙여.

    [c0] 2024-03-12 체중 92kg BMI 34.1
    [c1] 2024-06-20 체중 87kg HbA1c 7.1

    질문: 체중 변화는?"
   ↓
답: "체중 92kg에서 87kg으로 5kg 감소 [c0][c1]"
   ↓
검증: [c0],[c1]이 진짜 있나? → 있음 → 통과
      만약 [c9]라고 하면? → 없음 → 그 문장 삭제
```

**마지막 검증 단계가 우리 프로젝트의 심장입니다.** 차트원샷의 `enforce.ts`가 이걸 하고 있고, 온프렘에서도 그대로 씁니다.

## 5. 실습 C — LoRA, 실제로 해보기

여기가 요청하신 핵심입니다.

### C-0. 파인튜닝이란 게 정확히 무슨 일인가

한 문장으로: **"이 입력을 보면 이렇게 답해"라는 예시를 수백 개 보여주고, 모델이 그 답을 더 잘 맞히도록 숫자를 조금씩 미는 것.**

안에서 일어나는 일:

```
1. 예시 하나를 넣는다
   입력:  [c0] 45세 여자. 체중 92kg. 메트포르민 복용중.
   정답:  ## 인구통계
          45세 여성 [c0]
          ## 복용약
          메트포르민 (복용 중) [c0]

2. 모델이 자기 나름대로 답을 만든다
   → "45세 여성 환자로 비만이 있으며..."       (형식이 다름)

3. 정답과 얼마나 다른지 숫자로 잰다  ← 이게 loss
   → loss = 2.4

4. "다음엔 조금 덜 틀리도록" 숫자를 민다
5. 예시 300개 × 3바퀴 반복 → loss 2.4 → 1.1
   = 우리 형식을 익힘
```

**모델은 정답을 외우는 게 아니라 패턴을 익힙니다.** 300개를 보고
"아, 이 병원은 `## 항목명` 다음에 내용, 문장 끝엔 `[c번호]`구나"를 배웁니다.

### C-0.5. 파인튜닝이 고치는 것 / 못 고치는 것

| 고쳐줌 ✅ | 못 고침 ❌ |
|---|---|
| 출력 **형식**(항목·순서·인용 표기) | 없는 의학 지식 |
| 우리 병원 **말투·용어** | **환각** ← 인용 강제가 담당 |
| "이건 안 쓴다"는 **금지 패턴** | 원문에 없는 정보 |
| 항목 **선별 기준**(뭘 중요하다고 볼지) | 논리적 추론 능력 자체 |

**핵심: 파인튜닝은 재능을 주는 게 아니라 습관을 들이는 것입니다.**
환각은 파인튜닝으로 못 잡습니다 — 그건 `enforce.ts`(인용 없으면 삭제)의 일입니다.

### C-1. 그런데 — LoRA가 유일한 선택지가 아닙니다

**순서가 있습니다. 앞에서 끝나면 뒤로 안 갑니다.**

| # | 방법 | 학습 | 48GB에서 | 언제 |
|---|---|---|---|---|
| **0** | **프롬프트 + Few-shot** | 없음 | ✅ | **제일 먼저. 이것만으로 될 수도** |
| **0.5** | **구조화 강제 출력** | 없음 | ✅ | **형식 문제는 학습 없이 해결** |
| **1** | **RAG** | 없음 | ✅ | 긴 차트 문제 (우리 필수) |
| **2** | **QLoRA** | 작게 | ✅ | 위로 안 되면 |
| 3 | DoRA / rsLoRA | 작게 | ✅ | LoRA 변형, 조금 더 |
| 4 | DPO / ORPO | 작게 | ✅ | SFT 후 "이게 저것보다 낫다" |
| 5 | 프롬프트 튜닝 | 아주 작게 | ✅ | LoRA보다 가볍지만 성능 낮음 |
| 6 | **전체 파인튜닝** | 전부 | ❌ **불가능** | — |
| 7 | 추가 사전학습 | 막대함 | ❌ 불가능 | — |

**6번이 왜 불가능한지 — 숫자로:**

```
27B 모델을 통째로 학습하려면
  가중치      27B × 2바이트(bf16)  =  54GB
  그래디언트  27B × 2바이트        =  54GB
  옵티마이저  27B × 8바이트(Adam)  = 216GB   ← 범인
                                   ─────────
                                    324GB 이상

A6000은 48GB. 7배 부족. GPU 8장짜리 서버가 필요합니다.
```

QLoRA는 가중치를 4-bit로 **얼려두고**(13.5GB) 학습 대상이 **0.01%뿐**이라
옵티마이저가 거의 공짜입니다. 그래서 48GB에 들어갑니다.

### C-1.5. ★ 0.5번을 먼저 보세요 — 형식은 학습 없이 잡힙니다

vLLM에는 **구조화 강제 출력(guided decoding)** 이 있습니다.
JSON 스키마를 주면 **모델이 그 형식을 벗어난 글자를 아예 생성하지 못하게** 막습니다.
확률로 유도하는 게 아니라 문법적으로 차단합니다.

```python
response = client.chat.completions.create(
    model="medgemma-27b",
    messages=[...],
    extra_body={"guided_json": 우리_요약_스키마},   # schema.ts → JSON Schema
)
```

우리는 이미 `lib/summary/schema.ts`에 스키마가 있습니다.
**넘기기만 하면 "항목 순서 틀림", "필드 누락"이 학습 없이 사라집니다.**

> 그래서 파인튜닝이 필요한 진짜 이유는 형식이 아니라
> **"무엇을 중요하다고 볼 것인가"(항목 선별 기준)와 말투**입니다.
> IRB의 "1단계 추론 전용 → 2단계 QLoRA" 설계가 정확히 이 순서입니다.

### C-2. LoRA가 정확히 뭘 하나

흔히 "마지막에 모듈을 붙인다"고 하는데, 정확히는 **"마지막"이 아니라 여러 층 옆에 나란히** 붙습니다.

```
     원래 모델 (층이 60개쯤)
     ┌─────────┐
입력→│  1층    │→ ... 각 층 안에 거대한 숫자표가 여러 개
     ├─────────┤
     │  2층    │
     ├─────────┤
     │  ...    │
     └─────────┘
```

모델은 거대한 숫자 표(행렬) 수백 개입니다. 전체를 바꾸려면 270억 개를 다 건드려야 합니다 — 불가능합니다.

**LoRA는 원본을 안 건드리고, 옆에 작은 표 두 개를 새로 만들어 그것만 학습합니다.**

```
원래:   출력 = 원본표(거대) × 입력          ← 원본표는 잠가둠(동결)
LoRA:  출력 = 원본표(거대) × 입력  +  (작은표B × 작은표A) × 입력
                                      └──── 이것만 학습 ────┘
```

**왜 작은 표를 "두 개"로 나누나 — 이게 LoRA의 핵심 아이디어입니다.**

거대한 표가 `4096 × 4096`이면 **1,600만 개** 숫자입니다.
이걸 `4096 × 16` 하나 + `16 × 4096` 하나로 쪼개면 **13만 개**입니다. **120분의 1.**
곱하면 원래 크기로 돌아오니까 **같은 자리에 더할 수 있습니다.**

이 **16이 `rank`** 입니다. 작을수록 가볍지만 표현력이 제한됩니다.

**"제한된 표현력으로 충분한가?"** — 우리 작업엔 충분합니다.
새 의학 지식을 넣는 게 아니라 **형식과 스타일만** 가르치기 때문입니다.
형식 같은 건 "낮은 차원"에 살아서 작은 표로도 잡힙니다.
반대로 새 지식을 주입하려면 rank를 크게 키워야 하고, 그러면 LoRA의 장점이 사라집니다.

**결과: 학습해야 할 숫자가 270억 개 → 수천만 개로 줄어듭니다. 1000분의 1 이하.**

그리고 결과물은 **어댑터 파일 하나(수십~수백 MB)**입니다. 원본 모델 파일은 그대로 있습니다.

**Q(QLoRA)는 뭔가:** 원본 모델을 4-bit로 압축한 채로 LoRA를 하는 것. 책상을 덜 쓰므로 **우리 GPU에서 가능해집니다.** IRB에 적힌 게 이 방식입니다.

### C-2.5. ★ 진짜 문제 — 정답 300개는 어디서 나오나 (닭과 달걀)

여기가 이 프로젝트에서 **가장 많이 막히는 지점**입니다.

학습하려면 **이미 잘 뽑힌 요약 300개**가 필요합니다.
그런데 그게 있으면 애초에 도구가 필요 없습니다. **닭과 달걀입니다.**

**해법: 부트스트랩(bootstrap) — 스스로 끌어올리기**

```
1차   학습 없는 모델에게 그냥 시킴 (RAG + 프롬프트)
        ↓
      초안 100개 생성   ← 60%는 쓸만하고 40%는 엉망
        ↓
2차   교수님이 5개만 꼼꼼히 고침       ← IRB의 검수 상한이 5명
        ↓
      "고치기 전 → 고친 후" 5쌍 확보
        ↓
3차   이 5쌍의 패턴을 보고 나머지 95개를 규칙으로 수정
      (예: "전부 인과 표현 제거", "항목 순서 통일")
        ↓
      학습 데이터 100개 확보
        ↓
4차   LoRA 학습 → 다시 생성 → 교수님 재검수 → 반복
```

**이게 IRB에 적힌 "다수 사이클의 반복적 검수·개선"의 실체입니다.**

그리고 앞서 만든 **Interrogate 판정 결과가 여기 재료로 들어갑니다** —
교수님이 `[부적절]`이라고 누른 게 곧 **"이렇게 하지 마라"는 학습 신호**입니다.
검수가 곧 데이터 생산입니다. 따로 라벨링할 필요가 없습니다.

> **시간 배분 현실:** 모델 학습은 몇 시간이지만, 이 사이클은 몇 주입니다.
> "GPU가 느려서" 오래 걸리는 게 아니라 **사람 검수가 병목**입니다.

### C-3. 학습 데이터는 어떻게 생겼나

**이게 제일 중요합니다.** LoRA는 "이 입력에는 이렇게 답해"라는 예시를 보고 배웁니다.

`train.jsonl` — 한 줄이 예시 하나입니다:

```json
{"messages":[{"role":"system","content":"진료기록을 정해진 항목으로 요약한다. 각 문장 끝에 근거 [c번호]를 붙인다. 근거 없는 내용은 쓰지 않는다."},{"role":"user","content":"[c0] 2024-03-12 외래. 45세 여자. 체중 92kg BMI 34.1. 메트포르민 복용중. HbA1c 7.8%.\n[c1] 2024-06-20 외래. 체중 87kg. ```python
```
```python
# train_lora.py
import torch
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from trl import SFTTrainer, SFTConfig

BASE = "google/gemma-4-31b-it"       # 또는 Qwen3.6-27B, MedGemma-27B

# 1) 4-bit로 압축해서 불러오기 (QLoRA의 Q)
bnb = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",              # IRB에 적은 방식
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,
)

tok = AutoTokenizer.from_pretrained(BASE)
model = AutoModelForCausalLM.from_pretrained(
    BASE, quantization_config=bnb, device_map="auto"
)
model = prepare_model_for_kbit_training(model)

# 2) 붙일 메모지(LoRA) 설정
lora = LoraConfig(
    r=16,                    # ← IRB에 적은 rank=16
    lora_alpha=32,
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=["q_proj","k_proj","v_proj","o_proj",
                    "gate_proj","up_proj","down_proj"],
)
model = get_peft_model(model, lora)
model.print_trainable_parameters()
# → "trainable params: 3.4M || all params: 31,000M || trainable%: 0.011"
#   0.011%만 학습한다는 뜻. 이게 LoRA입니다.

# 3) 데이터
ds = load_dataset("json", data_files="train.jsonl", split="train")

# 4) 학습
trainer = SFTTrainer(
    model=model,
    train_dataset=ds,
    args=SFTConfig(
        output_dir="./adapter-fm-obesity",
        num_train_epochs=3,
        per_device_train_batch_size=1,
        gradient_accumulation_steps=8,
        gradient_checkpointing=True,     # 책상 절약. 느려지지만 켜야 함
        learning_rate=2e-4,
        logging_steps=5,
        max_seq_length=4096,
        bf16=True,
    ),
)
trainer.train()
trainer.save_model("./adapter-fm-obesity")
```

```python
# test_adapter.py
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

BASE = "google/gemma-4-31b-it"
tok = AutoTokenizer.from_pretrained(BASE)
base = AutoModelForCausalLM.from_pretrained(BASE, device_map="auto", load_in_4bit=True)

def ask(m, label):

    ids = tok.apply_chat_template(msgs, return_tensors="pt").to(m.device)
    out = m.generate(ids, max_new_tokens=300, temperature=0.0, do_sample=False)
    print(f"\n=== {label} ===")

ask(base, "학습 전")

tuned = PeftModel.from_pretrained(base, "./adapter-fm-obesity")
ask(tuned, "학습 후")
```

## 6. 실습 D — 잘했는지 어떻게 아나

### D-1. Precision / Recall 을 사과로

교수님이 "이 차트에서 중요한 항목 **10개**"를 정답으로 뽑았습니다(Gold Standard).
AI가 **8개**를 뽑았는데, 그중 **6개**가 정답과 일치했습니다.

| 지표 | 계산 | 뜻 |
|---|---|---|
| **Precision (정밀도)** | 6 ÷ 8 = **75%** | AI가 뽑은 것 중 맞은 비율 → *헛소리를 얼마나 안 하나* |
| **Recall (재현율)** | 6 ÷ 10 = **60%** | 정답 중 찾아낸 비율 → *얼마나 안 빠뜨리나* |
| **F1** | 둘의 조화평균 = **67%** | 종합 점수 |

**의료에서는 Recall이 더 중요합니다.** 헛소리는 사람이 지우면 되지만, **빠뜨린 건 아무도 모릅니다.**

### D-2. 우리만의 지표 두 개

| 지표 | 재는 것 |
|---|---|
| **span-level grounding** | `[c0]`이라고 한 인용이 진짜 그 위치에 있나 |
| **미등재 약어 원문 보존율** | 사전에 없는 약어를 멋대로 풀지 않았나 (**0건이 목표**) |

두 번째는 **환각 방지 원칙의 직접 측정**입니다. 여기서 1건이라도 나오면 IRB에 보고해야 하는 사안입니다.

### D-3. 반드시 지킬 것 — 환자 단위로 나누기

```
❌ 틀린 방법: 문서 1000개를 섞어서 800개 학습 / 200개 평가
   → 같은 환자의 3월 기록으로 배우고 6월 기록으로 시험 = 컨닝

✅ 맞는 방법: 환자 100명 중 80명 학습 / 20명 평가
   → 한 환자는 학습이든 평가든 한쪽에만
```

이걸 어기면 점수가 실제보다 높게 나오고, 논문에서 반드시 지적당합니다.

## 6.5 실습 E — AI에게 **스스로 의심하게** 시키기 (SEIG)

### 왜 이걸 하나

지금까지는 AI에게 **"요약해줘"**만 시켰습니다. 그런데 AI는 그럴듯한 거짓말을 합니다.

이런 요약이 나왔다고 해봅시다:

> **"생활습관 중재로 체중 7kg 감소 및 혈당 개선"** `[c0][c1][c2]`

인용도 붙어 있고 말도 됩니다. **그런데 틀렸습니다.**

차트에는 이렇게만 적혀 있습니다:
- `[c0]` 2024-03 체중 92kg, 식이상담 시행
- `[c1]` 2024-06 체중 87kg
- `[c2]` 2024-09 체중 85kg

**"상담을 했다"와 "체중이 줄었다"가 각각 있을 뿐, 둘이 원인-결과라는 근거는 어디에도 없습니다.**
메트포르민 때문일 수도, 갑상선 문제일 수도, 다른 병 때문일 수도 있습니다.

인용은 다 붙어 있으니 **우리 검증 로직도 이건 못 잡습니다.** 각 사실은 진짜니까요.
문제는 **사실들을 이어붙인 방식**입니다.

| **S**pecify (명세) | 뭘·누구에게·어디까지 시킬지 먼저 못박기 | 부분적으로 하고 있음 |
| **E**licit (도출) | 사실 / 추론 / 모르는 것을 **나눠서** 받기 | ✅ 하고 있음 (원문확정/추론/불확실 라벨) |
| **I**nterrogate (심문) | **첫 답을 캐묻기** — "이게 틀렸다면 왜?" | ❌ **안 하고 있음 → 이번에 추가** |
| **G**round (근거) | 모든 말에 출처 붙이기, 없으면 "차트에 없음" | ✅ 하고 있음 (인용 강제) |

**우리는 4개 중 3개를 이미 하고 있었습니다.** 빠진 건 **Interrogate 하나**입니다.

### 직접 해보기

Ollama를 켜고 이렇게 두 번 물어보세요.

**1차 — 그냥 요약 (지금 방식)**

```
아래 진료기록을 요약해줘. 각 문장 끝에 근거 [c번호]를 붙여.

[c0] 2024-03-12 외래. 45세 여자. 체중 92kg, BMI 34.1.
     메트포르민 복용 중. HbA1c 7.8%. 식이상담 시행.
[c1] 2024-06-20 외래. 체중 87kg. HbA1c 7.1%.
[c2] 2024-09-15 외래. 체중 85kg.
```

→ 아마 "생활습관 중재로 체중이 감소했다" 비슷한 답이 나옵니다.

**2차 — 스스로 의심하게 (Interrogate)**

```
방금 네가 쓴 요약을 다시 검토해줘. 아래 5가지 관점에서
"이 요약이 틀렸을 수 있는 지점"을 3개 찾아줘.

1. 인과 주장   — 원인-결과로 단정했는데 차트엔 근거가 없는 곳
2. 누락 감별   — 다른 원인을 배제하려면 필요한데 없는 검사
3. 측정 신뢰도 — 측정 조건이 기록되지 않아 비교가 어려운 수치
4. 약물 이력   — 용량 변경 기록이 없어 효과를 귀속할 수 없는 약
5. 확신도 과다 — 차트엔 수치만 있는데 판단처럼 서술한 표현

각 항목은 [유형] "문제되는 문장" — 왜 의심스러운지 형식으로.
```

→ 이런 게 나옵니다:

```
① [인과 주장] "생활습관 중재로 체중 감소"
   — 차트엔 상담 시행과 체중 감소가 각각 기록됐을 뿐 인과 근거 없음
② [누락 감별] 갑상선기능 검사 없음
   — 이차성 비만을 배제할 수 없음
③ [약물 이력] 메트포르민 용량 변경 기록 없음
   — 약물 효과를 배제할 수 없음
```

**이 차이를 눈으로 보는 게 이 실습의 전부입니다.** 같은 모델인데 한 번 더 물었더니
자기 답의 약점을 짚어냅니다.

### 우리가 만들 화면

교수님은 위 3개를 보고 **버튼만 누릅니다.**

```
① [인과 주장] "생활습관 중재로 체중 7kg 감소"
   차트에 인과 근거 없음        [ 타당 ] [ 부적절 ] [ 보류 ]
② [누락 감별] 갑상선 검사 없음   [ 타당 ] [ 부적절 ] [ 보류 ]
③ [약물 이력] 용량 변경 기록 없음 [ 타당 ] [ 부적절 ] [ 보류 ]
─────────────────────────────────────────────────
★ AI가 놓친 게 있나요?  (필수)
┌───────────────────────────────────────────┐
│                                           │
└───────────────────────────────────────────┘
```

> ### ★ 맨 아래 빈칸이 왜 필수인가
>
> AI가 3개를 띄우면 사람은 **"3개 다 봤으니 전부 검토했다"** 고 느낍니다.
> 그런데 AI가 못 떠올린 4번째 문제는 **영원히 안 나옵니다.**
> 논문이 이걸 **automation bias(자동화 편향)** 라고 부르며 직접 경고합니다.
>
> 이 빈칸은 장식이 아니라 **"AI가 얼마나 놓치는지"를 재는 유일한 수단**입니다.
> 여기에 교수님이 적은 게 많으면 → **우리 방식이 틀렸다는 신호**입니다.

## 6.6 오류에 이름 붙이기 (5분류)

지금은 오류가 나면 자유롭게 적어두고 있습니다. 이걸 **논문이 제시한 5개 이름**으로 통일합니다.

| 이름 | 무슨 뜻 | 우리 예시 |
|---|---|---|
| **fabrication** | 없는 걸 지어냄 | 차트에 없는 "가족력 당뇨"가 등장 |
| **omission** | 있는 걸 빠뜨림 | 알레르기 항목이 통째로 누락 |
| **unsupported certainty** | 근거 없이 단정 | **← 위의 "생활습관 중재로"가 여기** |
| **privacy breach** | 개인정보 노출 | 비식별에서 살아남은 이름이 요약에 등장 |
| **bias** | 특정 집단에 오류 몰림 | 고령 환자에서만 누락률이 높음 |

**왜 이름을 통일하나:** 다른 연구와 숫자를 비교할 수 있고, 논문 심사자가 이미 아는 분류라
설명이 짧아집니다. 하는 일은 **라벨 붙이기뿐**입니다.

### 하나 더 — 평균만 보면 안 됩니다

논문이 이렇게 경고합니다:

> *"오류는 하필 **기록이 가장 복잡한 환자**에게 몰릴 수 있다."*

그래서 전체 평균 F1 하나만 보고하면 안 되고, 나눠서 봐야 합니다:

- **기록이 긴 환자 vs 짧은 환자** — 긴 쪽에서 누락이 급증하는가
- **추적 기간 1년 미만 / 1~3년 / 3년 이상**
- **동반질환이 많은 환자 vs 적은 환자**
- 연령대·성별

**"평균은 괜찮은데 어려운 환자에서 무너진다"**면 그건 쓸 수 없는 도구입니다.
그리고 어려운 환자야말로 이 도구가 제일 필요한 사람들입니다.

## 6.7 실습 F — 약어집 만들기

### 하지 말아야 할 방법

교수님께 **"가정의학과에서 쓰는 약어 뭐뭐 있나요?"** 라고 묻는 것.

**사람은 자기가 매일 쓰는 약어를 기억으로 나열하지 못합니다.**
10개쯤 대다가 막힙니다. 그런데 실제 차트엔 50개가 넘게 나옵니다.

### 해야 할 방법 — 차트에서 먼저 뽑고, 교수님은 확인만

```
1단계  후보 자동 추출     ← 컴퓨터
2단계  빈도순 정렬        ← 컴퓨터
3단계  문맥 예문 수집     ← 컴퓨터
4단계  풀이 초안 제안     ← AI (확정 아님)
5단계  검수·확정          ← 교수님  ★ 여기만 사람
6단계  미등재 발견 → 루프
```

### 1단계: 후보 뽑기

약어는 형태가 특이해서 규칙으로 상당히 걸립니다.

```python
# abbrev_candidates.py
import re
from collections import Counter

PATTERNS = [
    r'\b[A-Z]{2,6}\b',              # HbA1c, BMI, NAFLD, OSA
    r'\b[a-z]/[a-z]\b',             # f/u, s/p, c/w
    r'\b[A-Z][a-z]?\d+[A-Za-z]*',   # T2DM, A1c
]
TOO_OBVIOUS = {"CT", "MRI", "OPD", "ER"}   # 설명이 필요 없는 것

def candidates(texts):
    c = Counter()
    for t in texts:
        for p in PATTERNS:
            c.update(x for x in re.findall(p, t) if x not in TOO_OBVIOUS)
    return c

# 사용
counts = candidates(모든_차트_텍스트)
for word, n in counts.most_common(50):
    print(f"{n:5d}  {word}")
```

### 2·3단계: 빈도순 + 예문

```
BMI     412회   "체중 92kg, BMI 34.1로 비만 2단계"
HbA1c   287회   "HbA1c 7.8%로 조절 불량"
f/u     201회   "3개월 후 f/u 예정"
NAFLD    88회   "복부초음파상 NAFLD 소견"
OSA      34회   "OSA 의심되어 수면다원검사 권유"
Rf        7회   "Rf 조절 필요"          ← ??? 애매함
```

**빈도가 중요합니다.** 412번 나오는 걸 틀리면 412번 틀립니다.
7번 나오는 건 나중에 해도 됩니다.

### 4단계: AI가 초안, 사람이 확정

```
AI 제안:  Rf = risk factor (위험인자)
근거:     "심혈관 Rf 조절" 문맥에서 사용
확신도:   낮음     ← 반드시 함께 표시
```

> **AI 풀이는 절대 그대로 등재하지 않습니다.**
> 그게 IRB의 "사전 기반 원칙"을 어기는 지름길입니다.
> 교수님 확인 전엔 **미등재 상태**로 둡니다.

### 5단계: 교수님 화면

```
┌────────────────────────────────────────────────┐
│ BMI  (412회)                                   │
│ 예문: "체중 92kg, BMI 34.1로 비만 2단계"       │
│ 제안: body mass index / 체질량지수             │
│                    [ 맞음 ] [ 수정 ] [ 제외 ]  │
└────────────────────────────────────────────────┘
```

**빈도순 상위 50개만 보시면 됩니다. 30분이면 끝납니다.**
반면 "생각나는 대로 적어주세요"라고 하면 며칠 걸리고 절반은 빠집니다.

### 6단계: 루프

운영 중 미등재 약어가 나오면 → 자동 로그 → 다음 검수 때 후보로 승격.
**Interrogate(실습 E)와 완전히 같은 구조**입니다.

### 왜 이게 값어치가 있나

IRB v3에 이렇게 적혀 있습니다:

> *"본 약어 사전은 환자 식별 정보나 특정 환자 의무기록 내용을 일체 포함하지 않음.
> **연구 종료 후에도 학술 자료로 공유 가능한 비식별 자료**에 해당함."*

즉 **차트는 못 내보내도 약어집은 내보낼 수 있습니다.**
논문 부록이나 별도 자료로 공개 가능한 산출물이 하나 생깁니다.
국내에 분과별 약어집이 제대로 정리된 게 없어서 그 자체로 인용될 수 있습니다.

### 사전 항목 형식 (IRB 규격)

```json
{
  "abbr": "f/u",
  "full": "follow-up",
  "ko": "추적 관찰",
  "scope": "가정의학과 · 양산부산대학교병원",
  "example": "3개월 후 f/u 예정",
  "verified_by": "자문교수",
  "verified_at": "2026-09-XX"
}
```

`verified_by`가 비어 있으면 **미등재로 취급해 풀이하지 않습니다.**


**4번에서 이미 충분할 수도 있습니다.** LoRA는 필요할 때만 합니다.

## 8. 자주 나는 에러

| 증상 | 원인 | 해결 |
|---|---|---|
| `CUDA out of memory` | GPU 책상 부족 | `max_seq_length` 줄이기 / `batch_size=1` / `gradient_checkpointing=True` |
| 모델이 안 켜짐 | 4-bit 설정 누락 | `load_in_4bit=True` 확인 |
| `loss`가 `nan` | 학습률 과다 | `learning_rate`를 `1e-4`로 |
| 답이 매번 다름 | temperature 높음 | `temperature=0`, `do_sample=False` |
| 다른 환자 정보가 섞임 | **환자 ID 필터 누락** | 벡터 검색 `query_filter` 확인 ← **최우선** |
| 인용 번호가 엉뚱함 | 청크 ID 매핑 깨짐 | 청킹 단계부터 다시 |
| `pip install` 안 됨 (①) | 인터넷 없음 | `--no-index --find-links` |

## 9. 한 장 요약

```
[준비]  ② PC에서 Ollama로 모델 한 번 돌려보기          ← 30분
        vLLM 서버 띄우고 curl로 불러보기                ← 1시간

[배관]  더미 차트로 청킹 → 임베딩 → Qdrant → RAG       ← 반나절
        ★ 환자 ID 필터 반드시 확인

[먼저]  0) 프롬프트 → 0.5) 구조화 강제 출력 → 1) RAG    ← 학습 없이 여기까지
        여기서 목표 도달하면 LoRA 안 해도 됨

[학습]  정답 데이터는 부트스트랩으로 만든다            ← 몇 주 (사람 병목)
          초안 생성 → 교수님 5개 교정 → 패턴 확장 → 반복
        QLoRA 학습 (rank=16, 4bit)                     ← 몇 시간
        어댑터 붙여서 전/후 비교

[검증]  Interrogate — AI가 자기 답 의심 지점 3개 제시
        교수님 판정 + "놓친 것" 자유칸 (필수)
        오류는 5분류로 이름 붙이기

[사전]  약어 후보 자동 추출 → 빈도순 → 교수님 30분 검수

[평가]  Precision / Recall / F1 + 인용 정확도 + 미포착률
        ★ 환자 단위로 나눌 것 (문서 단위 ✗)
        ★ 평균만 보지 말 것 — 기록 긴 환자에서 무너지는지

[이관]  반입 번들 만들어 ①에 설치 → 실데이터 실행
```

### 순서가 왜 이렇게 되나 — 한 문장씩

- **학습은 마지막입니다.** 프롬프트·구조화 출력·RAG로 먼저 해보고, 안 되면 그때 LoRA.
- **정답 데이터가 병목입니다.** GPU가 아니라 사람 검수가 일정을 정합니다.
- **검수가 곧 데이터 생산입니다.** Interrogate 판정 결과가 다음 학습 재료가 됩니다.
- **약어집은 물어보지 말고 뽑아서 보여주세요.** 사람은 자기 약어를 기억 못 합니다.
