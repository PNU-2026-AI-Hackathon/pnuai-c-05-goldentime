## 1. 차트원샷과 무엇이 다른가

이미 만든 차트원샷을 그대로 옮기는 게 **아닙니다.** IRB v3 §6(1)이 못박은 조항 때문입니다:

> "외부 장비 반입과 원내망 연결은 원천적으로 불가하므로 **외부 LLM·OCR API 호출 및 외부 클라우드 GPU 사용은 일체 수행하지 않음**"

| 항목 | 차트원샷 (현재) | 온프렘 연구도구 |
|---|---|---|
| 데이터 | 합성(Synthea) · MIMIC-IV 공개 비식별 | **실제 환자 비식별 EMR** (양산부산대병원) |
| 모델 | 클라우드 3-백본 (GPT-5.6 Sol · Claude Fable 5 · MedGemma) | **원내 온프렘 단일 모델**, 외부 호출 0 |
| 교차검증 | 3모델 상호 검증 | **자문 교수 Gold Standard 검수** |
| 배포 | Vercel 공개 웹 | 폐쇄망 내부 웹 UI (검수용) |
| 약어 | 분과 사전 lookup (일반) | **가정의학과·비만 전용 사전 신규 구축** |
| 평가 | 내부 회귀 지표 | precision/recall/F1 + 95% CI, 논문용 |

### 1.1 그대로 가져갈 수 있는 것 (실측 — 이미 repo에 있음)

| 자산 | 줄수 | 온프렘에서의 역할 |
|---|---|---|
| `lib/summary/enforce.ts` | 30 | **문장별 인용 강제** — IRB v3 §6(1) 환각 방지 원칙 ②의 구현체 |
| `lib/span.ts` | 43 | 원문 구간 매칭 → **span-level grounding accuracy** 지표 산출 |
| `lib/chunking.ts` | 29 | 청킹 + 청크별 인용 ID 부여 |
| `lib/deid/rules.ts` | 68 | 비식별 룰 — 분양 후 **2차 잔존 식별자 점검**용 |
| `lib/summary/schema.ts` | 61 | 요약 출력 스키마(zod) — 추출 항목 구조 정의 |
| `lib/verify/{harness,judge,diff}.ts` | 174 | 평가 하네스 — Gold Standard 대조 루프에 재사용 |
| `lib/specialties.ts` | 246 | 분과 정의 — 가정의학과 항목 정의의 출발점 |

**결정적으로 유리한 점 하나:** `package.json`에 이미 **`@ai-sdk/openai-compatible`**이 들어 있습니다. vLLM은 OpenAI 호환 엔드포인트를 열기 때문에, **provider 추상화를 그대로 두고 `baseURL`만 원내 주소로 바꾸면** 클라우드 → 온프렘 전환이 됩니다. 요약 로직·인용 강제·평가 하네스를 다시 쓸 필요가 없습니다.

### 1.2 새로 만들어야 하는 것

| 항목 | 이유 |
|---|---|
| **임베딩 + 벡터DB** | 현재 repo에 RAG 구현이 없습니다(확인함). IRB v3가 RAG를 필수 구성요소로 명시 |
| **OCR 교체** | 현재 `unpdf`(JS) → 온프렘 **PaddleOCR-VL**. 단 IRB상 OCR 용도는 *"외부 병원 영상판독지 분류·정리에 한정"* |
| **QLoRA 학습 파이프라인** | 현재 없음. 2단계 적응용 |
| **모델 서빙** | vLLM 기동·양자화·엔드포인트 |

## 2. 데이터 흐름 (단일 위치 원칙)

IRB v3 §10(2)의 **단일 보관 위치 원칙**이 아키텍처를 결정합니다.

```
[병원 EMR/PACS]
      │  (의료빅데이터센터 비식별화 담당자 — 병원 내부 책임자)
      │  1단계 직접식별자 삭제·가명화 → 2단계 간접식별자 일반화
      ▼
[비식별 처리 기록부]  ← IRB 보고용, 검토자 서명 포함
      │  분양
      ▼
╔══════════════════════════════════════════════════════════╗
║  의료빅데이터센터 5층 데이터센터 · 원내 폐쇄망             ║
║  ┌──────────────────────────────────────────────────┐    ║
║  │ 인프라 ①  RTX A6000 48GB / Threadripper PRO       │    ║
║  │  · 비식별 EMR 보관 (여기 밖으로 절대 안 나감)      │    ║
║  │  · 임베딩 · 벡터DB · LLM 추론 · QLoRA SFT · 평가   │    ║
║  │  · 산출물(요약문·지표·LoRA 어댑터)도 내부 보관     │    ║
║  └──────────────────────────────────────────────────┘    ║
╚══════════════════════════════════════════════════════════╝
      ▲
      │  ✗ 외부 매체(USB) 반출 금지  ✗ 외부 네트워크 송신 금지
      │  ✗ 외부 클라우드·API 호출 금지  (비식별 데이터라도 금지)
      │
[인프라 ②  진단검사의학과 PC · RTX 4080 16GB]
   허용 작업만: 코드 개발/디버깅 · 모델 가중치 다운로드/양자화 테스트
                · 합성 더미데이터 기반 파이프라인 동작 검증
   ✗ 실 EMR 데이터 절대 반입 금지
```

**운영 규칙 3가지 (여기서 사고가 납니다)**

1. **②에서 ①로는 코드만 간다.** 데이터는 반대 방향으로도 안 옵니다.
2. **모델 가중치는 ②에서 받아 물리 매체로 ①에 넣는다.** ①은 원내망 미등록이라 인터넷이 없습니다. → 초기 세팅 시 **필요한 모든 것을 한 번에** 옮겨야 합니다(모델·파이썬 휠·도커 이미지·폰트까지).
3. **①에서 나오는 산출물도 내부 보관.** 논문용 지표를 밖으로 빼려면 별도 절차 확인이 필요합니다 → §9 질문.

## 3. 파이프라인 단계

```
① 문서 수집        비정형 EMR 텍스트(SOAP·외래기록·처방) + 스캔 영상판독지
        ▼
② OCR              PaddleOCR-VL 1.5 (스캔 판독지 한정)
        ▼
③ 2차 비식별 점검   deid/rules.ts로 잔존 식별자 표본 점검 → 발견 시 센터 재요청
        ▼
④ 청킹             문서 자연 단위(외래 1회분/입원 1차분) + 메타데이터 부착
                   {환자ID, 상대시점, 문서종류, 분과}
        ▼
⑤ 임베딩·색인      EmbeddingGemma 300M → Qdrant (로컬 Docker)
        ▼
⑥ 검색(RAG)        ★ 환자 ID 필터 필수 — 환자 간 정보 혼입 방지
        ▼
⑦ LLM 추론         4-bit 양자화 모델 · vLLM · temperature 낮게
        ▼
⑧ 약어 해소        가정의학과·비만 사전 lookup, 미등재는 원문 유지 + "미등재" 표시
        ▼
⑨ 인용 강제        enforce.ts — 원문 근거 없는 문장 제거
        ▼
⑩ 출력             환자 단위 시계열 요약 (구조화 항목 + span 인용)
        ▼
⑪ Interrogate      ★ AI가 자기 답의 의심 지점을 스스로 3~5개 제시 (§3.5)
        ▼
⑫ 검수 UI          자문 교수용 웹 UI — 의심 지점별 판정 + "AI가 놓친 것" 자유 입력
```

### ⑥의 환자 ID 필터가 왜 ★인가

RAG가 환자 경계를 넘으면 **A 환자 요약에 B 환자 정보가 섞입니다.** 비식별 데이터라도 이건 임상적으로 치명적이고, 논문에서 가장 먼저 지적받을 지점입니다. 벡터 검색 시 `patient_id` 필터를 **애플리케이션이 아니라 DB 쿼리 레벨에서** 강제하고, 필터 누락을 잡는 회귀 테스트를 넣는 것을 제안합니다.

### 환각 방지 (IRB v3 §6(1) 4원칙의 구현 대응)

| IRB 원칙 | 구현 |
|---|---|
| ① 추출형 요약 | 프롬프트 제약 + ⑨ 인용 강제로 사후 차단 |
| ② 원문 인용 | `span.ts` 매칭 → 문서 ID + 문자 구간. 매칭 실패 문장은 **드롭** |
| ③ 보수적 파라미터 | `temperature 0~0.2`, `top_p` 제한 |
| ④ 사전 기반 약어 | 미등재 약어는 풀이 금지, 원문 유지 + 플래그 |

> 차트원샷에서 실제로 겪은 함정(`TS-010`): 관대한 파서가 누락 필드를 기본값으로 채우면 **"모델이 안 냈다"와 "우리가 채웠다"가 기록에서 영원히 구분되지 않습니다.** 온프렘에서도 같은 규칙을 씁니다 — 기본값을 넣으면 *넣었다는 사실*을 함께 남깁니다. 이건 평가 지표의 신뢰성 문제라 논문에 직결됩니다.

## 3.5 SEIG 루프 — 채택 범위

### 근거 문헌

> Paulus MP, Torous J. **LLMs as Clinical Instruments—Toward Verifiable Reasoning.**
> *JAMA Psychiatry.* Published online July 29, 2026. doi:10.1001/jamapsychiatry.2026.2211

LLM을 자율적 임상 행위자가 아니라 **임상 도구(clinical instrument)** 로 다루기 위한 4단계
상호작용 루프를 제안한 Viewpoint. 논문 표현으로 이 루프는 LLM을 *answer generator* 에서
**bounded hypothesis generator** 로 바꿉니다.

| 단계 | 내용 | 우리 현황 |
|---|---|---|
| **Specify** | 과제·수신자·허용 출처·출력 형식 + **위임하지 않을 것** | 🟡 분과 관점·출력 스키마는 있음. 수신자/비위임 범위는 미정의 |
| **Elicit** | 사실 / 추론 / 누락 / 불확실을 분리해 받기 | ✅ 라벨 3종(`explicit`/`derived`/`uncertain`) + `gaps` 필드로 이미 구현 |
| **Interrogate** | 첫 답을 캐묻기 — 대안 설명·반례·편향·"무엇이 참이면 이 결론이 틀리나" | ❌ **없음 → 이번에 신설** |
| **Ground** | 모든 사실 주장을 출처에 연결, 없으면 "not in record" | ✅ `enforce.ts`(인용 없는 문장 삭제) + `span.ts`(구간 매칭) |

**즉 SEIG는 새 개념이 아니라 이미 만든 것에 국제 저널 프레임을 붙여주고, 빠진 조각 하나를
정확히 지목해 줍니다.**

### 채택 결정 (2026-08-03)

| 항목 | 결정 | 사유 |
|---|---|---|
| Interrogate를 **누가** 하나 | **(c) AI가 후보 제시 + 교수 판정 + "놓친 것" 자유 입력** | IRB상 자문 교수 검토 상한이 환자 **5명**. 교수가 매번 질문을 창안하면 5명도 벅참. 검수 시간을 아껴 케이스 수를 늘리는 게 본 연구(도구 검증) 목적에 부합 |
| Interrogate 기능 | **채택** | SEIG 4단계 중 유일한 미구현. 우리 차별점(감사·검증)의 직접 확장 |
| 오류 분류 체계 | **채택** | 라벨만 통일하면 되고, 국제 비교 가능성이 생김 |
| SEIG 기반 평가 rubric | **제외** | 임상의 상호작용 품질 채점은 본 연구 범위(도구 검증) 밖. IRB 관찰항목 변경 부담도 큼 |

> **(c)를 택할 때 반드시 지켜야 할 것 — 자동화 편향(automation bias)**
> 논문이 직접 경고하는 위험입니다. AI가 의심 지점 3개를 띄우면 검수자는
> *"3개 다 봤으니 전부 검토했다"* 고 느끼고, **AI가 못 떠올린 4번째 문제는 영원히 드러나지
> 않습니다.** 그래서 **"AI가 놓친 게 있나요?" 자유 입력칸을 필수**로 둡니다.
> 이 칸은 UI 장식이 아니라 **아래 미포착률 지표의 유일한 측정 수단**입니다.

### Interrogate 단계 설계

**입력:** 생성된 요약 + 근거로 쓰인 청크
**출력:** 의심 지점 3~5개 (유형 라벨 + 해당 문장 + 왜 의심스러운가)

비만 도메인에서 AI가 점검해야 할 유형:

| 유형 | 비만 케이스 예시 |
|---|---|
| **인과 주장** | "생활습관 중재로 체중 7kg 감소" — 차트엔 상담 시행과 체중 감소가 각각 있을 뿐, 인과 근거 없음 |
| **누락 감별** | 6개월간 갑상선·코르티솔 검사 없음 → 이차성 비만 배제 안 됨 |
| **측정 신뢰도** | 체중 측정 조건(공복/식후·시간대)이 기록에 없음 |
| **약물 이력 공백** | 메트포르민 용량 변경 기록 없음 → 효과 귀속 불가 |
| **확신도 과다** | "개선"이라고 서술했으나 차트엔 수치만 있고 임상 판단 기술 없음 |

│                        [ 타당 ] [ 부적절 ] [ 보류 ]      │
│ ────────────────────────────────────────────────────    │
│ ★ AI가 놓친 게 있나요? (필수 확인)                       │
│ ┌─────────────────────────────────────────────────┐    │
│ │                                                 │    │
│ └─────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────┘
```

**판정 결과는 그대로 평가 데이터가 됩니다** — 별도 라벨링 작업이 필요 없습니다.

### Interrogate 평가 지표 2개

| 지표 | 계산 | 의미 |
|---|---|---|
| **Interrogate 정밀도** | `[타당] 판정 수 ÷ AI 제시 수` | AI가 헛다리를 얼마나 안 짚나 |
| **AI 미포착률** | `교수가 자유칸에 새로 적은 문제 수 ÷ (AI 제시 [타당] + 교수 추가)` | **AI가 놓치는 비율 — 자동화 편향의 실측치** |

**미포착률이 이 설계의 핵심 지표입니다.** 이게 높으면 (c) 방식 자체가 위험하다는 신호이고,
그때는 (b)(교수가 직접 질문 창안)로 되돌려야 합니다. 즉 **우리 설계가 틀렸을 때
그것을 알려주는 장치**를 지표 안에 넣어 둔 것입니다.

## 4. 가정의학과 · 비만 특화 설계

### 4.1 이 진단군이 파일럿에 유리한 이유

IRB v3의 선정 사유(*"외래 위주 텍스트 기록이 풍부하고 기저질환·복용약·알레르기 등 추출 항목이 임상적으로 명확함"*)에 더해, 비만 코호트는 기술적으로 이런 장점이 있습니다:

- **시계열이 길고 규칙적** — 체중·BMI·대사지표가 반복 측정되어 **환자 단위 시계열 요약**의 검증 대상으로 이상적
- **수치 추출 정답이 명확** — 체중·BMI·허리둘레는 자유서술이 아니라 수치라 precision/recall 판정에 모호성이 적음
- **동반질환이 정형적** — 당뇨·고혈압·이상지질혈증·지방간이 반복되어 추출 항목 정의가 수렴
- **약물 변경 이력이 풍부** — 비만·당뇨 약제 변경이 잦아 "복용 중 vs 중단" 구분 검증에 적합

### 4.2 추출 항목 초안 (자문 교수 확정 필요)

IRB v3의 기본 항목에 비만 특화 항목을 더한 안입니다.

| # | 항목 | 형식 | 비만 특화 |
|---|---|---|---|
| 1 | 인구통계 | 연령대·성별 (범주) | |
| 2 | 주호소 | 텍스트 | |
| 3 | **체중·BMI 시계열** | 수치 + 상대시점 | ★ |
| 4 | **허리둘레·체성분** | 수치 (있는 경우) | ★ |
| 5 | 기저질환·진단명 | 시계열 순 | 당뇨·고혈압·이상지질혈증·지방간 |
| 6 | 복용약 | 현재 / 중단 구분 | ★ 비만·당뇨 약제 변경 이력 |
| 7 | 알레르기 | 목록 | |
| 8 | 수술력 | 시계열 | ★ 비만대사수술 여부 |
| 9 | **주요 검사결과** | 시계열 변화 | ★ HbA1c·지질·간효소 |

| 12 | 해결된 과거 이슈 | 분리 표기 | |

**미팅에서 확정할 것:** 3·4·10번이 실제 차트에 얼마나 일관되게 기록되는지. 기록이 산발적이면 정답셋 구성이 어렵습니다.

### 4.3 약어 사전 (가정의학과 20~50개 목표)

IRB v3 규격대로 `약어 / 풀네임 / 한국어 의미 / 적용범위 / 예문` 5필드. 착수용 후보:

```
BMI   body mass index          체질량지수
WC    waist circumference      허리둘레
HbA1c hemoglobin A1c           당화혈색소
FBS   fasting blood sugar      공복혈당

## 5. 인프라 · 모델 운영

### 5.1 VRAM 예산 ⚪ (추정 — 실측 전)

| 모델 | 4-bit 가중치 | A6000 48GB 추론 | 4080 16GB 추론 | A6000 QLoRA SFT |
|---|---|---|---|---|
| Gemma 4 31B | ~15.5GB | 여유 | ✗ | 가능(추정) |
| Qwen3.6 27B | ~13.5GB | 여유 | 빠듯 | 가능(추정) |
| MedGemma 27B | ~13.5GB | 여유 | 빠듯 | 가능(추정) |
| GPT-OSS 20B | ~10GB | 여유 | 가능 | 여유(추정) |

**"추정"이라고 쓴 이유:** 실제 소요는 KV 캐시(컨텍스트 길이 × 배치)와 activation에 크게 좌우되고, 저는 이 조합을 실행해본 적이 없습니다. **인프라 ②(4080)에서 더미데이터로 먼저 실측**한 뒤 확정하는 것을 제안합니다 — 이게 ②의 허용 용도("모델 가중치 다운로드 및 양자화 테스트")에 정확히 해당합니다.

RAG를 쓰므로 전체 차트를 컨텍스트에 넣지 않아도 되어, 컨텍스트를 짧게 유지하면 여유가 커집니다.

### 5.2 모델 선정 전략

IRB v3는 4개 후보 병렬 비교를 명시합니다. 파일럿에서는 이렇게 좁힐 것을 제안합니다:

1. **1차: GPT-OSS 20B로 파이프라인 완주** — 가장 가벼워 반복 주기가 빠릅니다. 성능이 아니라 **배관 검증**이 목적
2. **2차: MedGemma 27B vs Qwen3.6 27B 비교** — 의료 특화 vs 한국어 강세의 대결. 한국어 EMR이라 이 비교가 실질적입니다
3. **3차: 승자에 QLoRA 적용** — 1단계(추론) 목표 미달 시에만

> MedGemma 관련 실측 경험 하나: 차트원샷에서 MedGemma가 **인용을 별도 필드가 아니라 본문에 `[c33]` 형태로 인라인 표기**해서 파서가 통째로 버린 적이 있습니다(`TS-010`). 온프렘에서도 모델별 출력 형식 편차를 **수리 전 원문 단계에서** 먼저 확인해야 합니다. 후처리를 통과한 데이터로 모델 성능을 판단하면 오귀속이 납니다.

### 5.3 적응 단계 (IRB v3 §6(1) 그대로)

```
1단계  추론 전용 (RAG + Few-shot)          ← 베이스라인, 여기서 끝날 수도 있음
2단계  QLoRA SFT (rank=16, NF4 4bit)       ← 목표 미달 시
       학습 예제 200~500개 (환자 100명에서 도출)
       베이스 가중치 동결, LoRA 어댑터만 학습·저장
3단계  DPO                                  ← 옵션, 2단계 결과 보고 판단
```

추출·분류형 작업이라 **2단계까지로 목표 도달이 예상**된다는 게 IRB의 판단이고, 저도 동의합니다.

## 6. 평가 설계

### 6.1 데이터 분할 — 환자 단위 분할 필수

동일 환자의 문서가 학습/평가에 흩어지면 **data leakage**입니다. `patient_id` 기준으로 폴드를 나눕니다(IRB v3 명시).

```
가정의학과 비만 환자 100명
  ├─ Gold Standard  5명   ← 자문 교수 직접 검수 (가장 복잡한 케이스)
  └─ 나머지 95명          ← 환자 단위 K-fold 또는 전수 평가
```

### 6.2 지표

**(가) 추출 항목 정확도**
- 항목별·전체 Precision / Recall / F1 + **95% 신뢰구간**
- 누락률 (정답셋에 있는데 못 뽑은 비율)
- 오분류율 (뽑았는데 교수가 부적절 판정한 비율)
- **span-level grounding accuracy** (인용이 실제 원문 위치와 일치하는가) ← `span.ts`로 이미 산출 가능

**(나) 약어 해소**
- 등재 약어 해소 정확도
- **미등재 약어 원문 보존율** ← 환각 방지 원칙의 직접 측정
- **환각 발생 건수** (미등재 약어를 임의 풀이한 사례) — 0이 목표, 발생 시 원칙 위배로 별도 보고

### 6.3 오류 분류 체계 (채택 — 2026-08-03)

지금까지 오류를 자유 서술로 기록해 왔습니다(`docs/verification/error-injection-log.md`).
이를 위 논문이 제시한 **5분류 표준**으로 통일합니다. 새로 할 일은 라벨 붙이기뿐이고,
얻는 것은 **다른 연구와 숫자 비교가 가능해진다는 점**입니다.

| 분류 | 정의 | 가정의학과·비만 케이스 |
|---|---|---|
| **fabrication** | 차트에 없는 내용을 지어냄 | 기록에 없는 "가족력 당뇨"가 요약에 등장 |
| **omission** | 있어야 할 내용을 빠뜨림 | 알레르기 항목이 통째로 누락 |
| **unsupported certainty** | 근거 없는 확신 | **"생활습관 중재로 체중 감소"** — 상관을 인과로 서술 |
| **privacy breach** | 식별정보 노출 | 비식별에서 살아남은 이름·번호가 요약에 등장 |
| **bias** | 특정 집단에 오류 편중 | 특정 연령대·성별에서 누락률이 유의하게 높음 |

**층화 분석 추가 (논문 권고 반영)**

> *"감사는 문서 작성 스타일·언어 능숙도·인구학적 맥락에 걸쳐 수행해야 한다. **오류는 하필
> 기록이 가장 복잡한 환자에게 몰릴 수 있기 때문이다.**"*

우리 맥락으로 옮기면 — **전체 평균 F1만 보고하면 안 됩니다.** 다음 축으로 나눠 봅니다:

| 층화 축 | 확인할 것 |
|---|---|
| **기록 분량** (문서 수·토큰 수 상·중·하) | 긴 차트에서 누락률이 급증하는가 |
| **추적 기간** (1년 미만 / 1–3년 / 3년 이상) | 시계열이 길수록 무너지는가 |
| **동반질환 수** | 복잡할수록 오분류가 느는가 |
| 연령대·성별 | 특정 집단 편중이 있는가 |

**Gold Standard 5명이 "가장 복잡한 케이스 우선"으로 선정된다는 점**(IRB v3)이 여기서
의미를 갖습니다 — 가장 어려운 구간을 먼저 보는 설계이므로, 층화 결과를
**"최악 구간 성능"** 으로 해석해 보고할 수 있습니다.

### 6.3 표본 5명의 한계는 미리 적는다

Gold Standard 5명으로 산출한 95% CI는 매우 넓습니다. **이걸 논문에서 숨기면 안 됩니다.** IRB v3도 *"95% 신뢰구간 (표본 크기 한계 명시)"*라고 이미 못박아 뒀습니다. 검수 사이클을 돌려 정답셋을 늘리는 게 계획에 포함돼 있으니, **1차 결과는 "파일럿 타당성 확인"으로 위치**시키는 게 맞습니다.

## 9. 미팅에서 결정이 필요한 것

**교수님께 여쭐 것 (우선순위 순)**

1. **대표 진단군을 "비만"으로 확정해도 되는지** — IRB v3 표에 아직 `?`입니다. 확정되어야 분양 신청서를 씁니다.
2. **추출 항목 12개(§4.2) 중 실제 차트에 일관되게 있는 것은?** 특히 **체성분·허리둘레·생활습관 상담 기록**. 없으면 항목에서 빼야 정답셋이 성립합니다.
3. **"복용 중 vs 중단" 구분이 차트에 명시되는지**, 아니면 추론이 필요한지. 추론이면 난이도가 크게 오릅니다.
4. **Gold Standard 5명 검수에 쓰실 수 있는 시간** — 1인당 소요를 알아야 사이클 수를 잡습니다.
5. **DRB 신청 현재 상태와 예상 소요** — 일정의 임계 경로입니다.
6. **산출물(지표·요약문 샘플)의 반출 절차** — 논문·발표에 쓰려면 5층 밖으로 나와야 하는데, 이 경로가 IRB 문서에 명시돼 있지 않습니다.
7. **SEIG Interrogate 도입에 IRB 변경신청이 필요한지** — 관찰항목(§8)에 "의심 지점 판정 결과"와 "AI 미포착 사례"가 추가됩니다. 평가 rubric은 도입하지 않기로 해 §9 자료분석은 그대로입니다.
8. **비만 코호트 환자 100명이 실제로 확보되는지** — 5개년(2020~2024) 범위에서 추출 조건을 좁혔을 때의 실제 건수.

| | 가능 여부 |
