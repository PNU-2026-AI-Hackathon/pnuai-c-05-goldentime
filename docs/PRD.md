# PRD — 차트원샷 검증·감사 하네스 (Verification & Audit Harness)

> 상태: Draft v0.1 · 2026-07-15 · Team Golden Time
> 관련 문서: [DEVELOPMENT-NOTES.md](./DEVELOPMENT-NOTES.md) · [ERD.md](./ERD.md)

## 0. Overview (기획서 요약)
속도("초 단위")는 곧 상향평준화될 commodity다. **한 번의 오류도 허용 안 되는 의료 도메인**에서 차트원샷의 진짜 차별점은 →

> **"불확실성을 정직하게 드러내고, 다중 모델로 검증하며, 감사(audit) 가능한 요약."**
> = **감사 · 검증 · 하네스.**

서호건 박사 자문 근거: ① 멀티에이전트 peer review는 **백본이 다른 모델**로 ② 합성데이터에 **의도적 오류 주입**으로 벤치마크 ③ **로컬 모델 우선**(클라우드는 PoC, 로컬은 "차원이 다르다") ④ **문제를 먼저 드러내기**(에러가 터져야 문제정의가 명확) ⑤ 원문 무교정(오탈자도 hallucination 방지 차원에서 보존).

## 1. Goals / Non-goals
**Goals**
- G1. 검증 과정을 **투명하게 공개**해 전문가(교수·심사위원) 신뢰 획득.
- G2. **오류주입 벤치마크**로 "우리가 뭘 잡고 뭘 놓치는지" 정직하게 노출.
- G3. **다중 모델 교차 검증**(클라우드 2종 · 로컬 1종)로 불일치 탐지 → 교수 자문 → 반영 루프.
- G4. **누락(omission)**과 **불확실성**을 숨기지 않고 화면에 드러냄.
- G5. 모든 오류·트러블슈팅을 **가감없이 기록**(원장) → 큐레이션본 공개.

**Non-goals (명시적 배제)**
- N1. 프로덕션 **매 요약에 멀티에이전트** — 오버엔지니어링. 프로덕션 hot-path는 단일 모델 + 인용강제. 멀티에이전트는 **오프라인 검증 레이어 전용**.
- N2. **사용자 제출물 공개** — 동의 범위(품질개선) 초과 + 비식별 불완전 → 관리자 전용.
- N3. **빠른/정밀 모드 선택권** — 주지 않는다. 의료계는 보수적: **느려도 정밀검증 단일 트랙**.

## 2. Users / Roles
| 역할 | 권한 |
|---|---|
| 방문자(교수·심사위원) | 공개 검증 리포트 열람 |
| 인증 교수 | 라이브 재현(게이트) + 자문 주석 |
| 관리자(팀) | 전체 원장·트러블슈팅·재실행·오류주입 케이스 관리 |

## 3. 2-Way Split (핵심 설계)
| | 공개 (비번 X) | 게이트 (서버측 비번) |
|---|---|---|
| 데이터 | **합성 + 의도적 오류주입** (PHI 없음) | **인증된 사용자가 직접 입력한 데이터** |
| 실행 | **미리 계산**(pre-computed) → 무료·즉시 | **라이브 3모델**(real cost) |
| 워닝 | 없음 | "실제 프론티어 3모델을 라이브 호출하는 정밀 검증 — 신중히" (비용은 진지함의 근거로만) |
| 보호 | — | 서버측 비번 + **하루 N회 비용상한** |

## 4. Features
### F1. 공개 "검증·신뢰" 섹션 (메인 페이지)
- 큐레이션된 3모델 불일치 케이스 + 교수 검증 주석 + 대표 오류/처리.
- **수용기준:** 실물 결과가 **최소 1개라도 교수 검증**된 뒤에만 노출(빈 껍데기 금지). 모두 pre-computed, 로딩 즉시.

### F2. 오류주입 벤치마크
- 합성에 **의도적 오류** 주입: `페니실린 알레르기 + 페니실린 처방` / `신부전 + 조영제·NSAID` / `약물상호작용` / `오타·모순·애매함`.
- 각 모델의 탐지/불확실표시 여부 측정.
- **수용기준:** 케이스마다 **의도·주입 프롬프트·변경점(diff)**을 [error-injection-log.md](./verification/error-injection-log.md)에 **가감없이** 기록.

### F3. 3-백본 peer-review 하네스
- 모델: **클라우드 모델 2종 · 로컬 모델 1종**. 백본 다양성 = 독립 검증. (동일모델 페르소나 X)
- 3자 출력 비교 → 불일치 필드 추출 → 관리자/교수 자문 큐로.
- **로컬 vs 클라우드 격차**(F8)의 데이터 출처이기도 함.

### F4. 게이트 라이브 재현
- 교수가 실제 데이터 붙여넣기 → 라이브 3모델 실행.
- 모달: 서버측 비번 + 워닝 + 나머지 화면 딤드. **하루 N회 비용상한(서버)**.
- **수용기준:** 비번은 **서버 라우트에서 검증**(클라이언트 노출 금지). 상한 초과 시 차단.

### F5. 관리자 검증 원장 (`/admin`)
- 전체 검증 실행 로그 · 트러블슈팅 · **불일치→교수자문→반영 타임라인** · 재실행 · 사용자 제출물(비공개).
- **수용기준:** 서버 인증(env `ADMIN_SECRET`). 데이터는 인증된 서버 라우트로만 반환.

### F6. 누락(omission) 투명성 패널
- 요약이 원문에서 **뺀 것 + 왜 뺐는지**(저신뢰·무인용)를 명시. "뺀 것도 보여준다."

### F7. 원문 무교정 원칙
- 오탈자·표기를 **자의적으로 고치지 않고 그대로 보존**(기록물). 원칙을 명문화·노출.

### F8. 클라우드 vs 로컬 격차 시각화
- 클라우드 모델은 잡는데 **로컬 모델은 놓친 케이스** = 우리가 풀 문제(해자·로드맵).

## 5. 데이터 거버넌스 / 보안
- 공개 = **합성 only**. 사용자 제출물은 **절대 공개 금지**(관리자 전용).
- 비번 = **서버측**. 관리자 데이터 = 인증 라우트로만.
- 라이브 경로 = **비용 상한** 필수(비번 유출 대비).

## 6. Success Metrics
- 공개 검증 케이스 수(교수 검증 완료분) · 모델별 오류 탐지율 · 트러블슈팅 원장 항목 수(투명성 지표) · 클라우드↔로컬 격차 케이스 수.

## 7. Milestones
- **M0** 기록 인프라(원장·PRD·ERD) — *진행중*
- **M1** 오류주입 벤치마크 3~5케이스 실물 (클라우드 1종 먼저 → 나머지 순차 연결)
- **M2** 공개 검증 섹션 + 누락패널(F6) + 무교정 원칙(F7) + Features 압축
- **M3** `/admin` 서버 게이트 + 원장 뷰(F5)
- **M4** 게이트 라이브 재현(F4) + 워닝모달 + 비용상한

## 8. Risks
| 리스크 | 완화 |
|---|---|
| 실물 없는 공개(IRB·병원 과장과 같은 함정) | **교수 검증 실물 확보 후에만** 공개 |
| 클라이언트 비번 노출 | 서버측 검증 · 인증 라우트 |
| 로컬 모델 성능 한계 → 불일치 오해 | "불일치=진짜 애매함"이 아님을 교수가 판정 |
| 라이브 비용폭탄 | 서버 비용상한 |
| 사용자 제출물 유출 | 공개 화면에 절대 미포함 |
