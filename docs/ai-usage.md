## 1. 활용한 AI 도구

| 도구 | 용도 | 단계 |
|---|---|---|
| **Claude Code** | 주 개발 도구 — 설계 문서화, 구현, 테스트 작성, 리팩터링 | 개발 |
| **타 계열 코딩 모델** | read-only **교차 리뷰** — 작성한 모델이 아닌 다른 계열이 검토 | 리뷰 |
| **GPT-5.6 Sol · Claude Fable 5 · MedGemma 27B** | 제품 기능 — 요약 생성 및 3-백본 교차 검증 | 제품 |
| **MITRE Synthea™** | 합성 환자 데이터 생성 (LLM 아님, 규칙 기반 시뮬레이터) | 데이터 |

## 2. 활용 범위 — 쓴 곳과 쓰지 않은 곳

**쓴 곳**

- 요구사항·설계 문서 초안 작성 및 설계안 2~3개 비교
- 애플리케이션 코드, 자동화 테스트, 비식별 파이프라인 구현
- 시연영상 빌드 파이프라인 스크립트화 (`docs/demo-video/` — 카드 렌더·자막·BGM)
- 문서 교정 및 구조화

**의도적으로 쓰지 않은 곳** — 이 경계가 이 프로젝트의 핵심입니다.

| 영역 | 이유 |
|---|---|
| **의학적 오류 시나리오 설계** | 현실성이 없으면 검증이 무의미합니다. 시나리오는 **자문 교수가 co-design**하고 AI는 정해진 규칙대로 변조만 수행합니다 |
| **팀 이력·수상 실적 서술** | 창작 금지. 확인된 사실만 기재하며, 결과 미확정 항목은 "진행 중"으로 분리 표기합니다 |
| **실제 환자 데이터 처리** | IRB 미승인 상태이므로 실데이터는 다루지 않습니다. 차트 코퍼스의 텍스트 추출도 **전량 로컬**(PyMuPDF)에서 수행해 외부 전송이 없습니다 |
| **정확도·성능 수치 생성** | 실행 기록으로만 산출합니다. 측정하지 않은 값은 적지 않습니다 |

## 3. AI 생성 코드의 검증·수정 방식

AI가 쓴 코드는 **기본적으로 신뢰하지 않는다**는 전제로 4단계를 거칩니다.

**① 기계 게이트 (통과 못 하면 완료 아님)**

```
npx tsc --noEmit     # 타입 오류 0
npm run build        # 프로덕션 빌드 성공
npm test             # vitest
```

최근 실측 — **197 passed / 2 skipped (테스트 파일 30 passed / 2 skipped)**.
"동작한다"는 주장은 실제 실행 출력이 있을 때만 인정하며, 출력 없는 완료 보고를 금지합니다.

**② 교차 리뷰 — 다른 계열 모델에게 맡깁니다**

같은 모델에게 자기 코드를 검토시키면 대체로 통과시킵니다. **다른 계열 모델에 read-only로**
리뷰를 맡겼을 때 비로소 타입 교차 버그·예외 처리 누락·보안 정책 불일치가 잡혔습니다.

> 이 경험이 그대로 제품 설계로 이어졌습니다 — **3개 백본이 각각 독립으로 요약하고
> 불일치만 추출하는 교차 검증**은 개발 과정에서 얻은 교훈을 제품 기능으로 승격시킨 것입니다.

**③ 오류주입으로 탐지력 측정**

의도적으로 오류를 심은 합성 케이스를 만들어 파이프라인이 실제로 잡는지 측정합니다
(알레르기 금기, 신독성 금기, 오탈자 보존, 누락 탐지 등). 목적은 통과가 아니라
**검출되지 않는 오류 유형을 특정**하는 것입니다. → `docs/verification/error-injection-log.md`

**④ 실패를 남기는 규율**

- 프로젝트 규칙을 `CLAUDE.md`에 고정해 **세션마다 자동 적용**합니다 — 작업 순서(설계 승인 전 구현 금지),
  기록 의무, 완료 게이트, 데이터 거버넌스.
- 오류·버그·삽질은 만나는 즉시 트러블슈팅 원장에 `증상·진단·수정·검증·교훈`으로 남깁니다.
- 비식별 로직에서 나온 결함 2건은 원인과 교훈을 **문서로 공개**했습니다 → [`docs/verification/deid-lessons.md`](verification/deid-lessons.md)
  핵심은 *"자기 규칙으로 자기를 검사하면 맹점이 그대로 상속된다"* 였고, 이는 AI 코드를
  같은 모델에게 검토시킬 때의 문제와 정확히 같은 구조였습니다.

## 4. 한계 (정직하게)

- AI는 **그럴듯하지만 틀린 코드**를 만듭니다. 위 4단계는 이를 줄이는 장치일 뿐 없애지 못합니다.
- 자동화 테스트가 통과해도 **테스트하지 않은 경로의 결함은 남습니다.**
- 현재 공개된 모든 수치는 **합성 데이터 기준**입니다. 실데이터 성능은 IRB 승인 후에야 말할 수 있습니다.
